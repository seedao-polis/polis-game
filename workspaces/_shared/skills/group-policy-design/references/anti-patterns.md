# 反模式：设计多人多群组策略时常踩的坑

<overview>
这些是把【按群按人差异化】做坏的典型方式。设计与落地前对照排查。
</overview>

<anti_pattern name="误写全局、漏带命名空间">
**问题**：写一条本该属于某人的记忆时漏了命名空间，或图省事写进 `global`。
**后果**：本该只有 A 看到的内容，变成人人可见——跨人隔离被绕过。
**正确做法**：写入必带命名空间，按 `context-model.md` 的决策树选定。个人事实一律 `user:{open_id}` / `private`。命名空间无默认值正是为了逼你显式选择。
</anti_pattern>

<anti_pattern name="把保密寄望于记忆硬闸">
**问题**：以为【标了工作群层级，工作群的个人记忆就不会进公开群】。
**后果**：个人记忆 `user:` 跨群通用，分级**不**在记忆层硬过滤；高密内容可能在低密群被注入。
**正确做法**：分清两种隔离——跨人靠命名空间（硬），跨层级靠分级提示（软）。真要硬隔离来源层级，需另加机制（给记忆加来源层级标记 + 读取按当前群过滤），并先跟用户确认值不值得。
</anti_pattern>

<anti_pattern name="设了策略却没加 listen">
**问题**：在 `chat-policies.json` 里精心配了某群的层级与专属提示，但没把这个群加进该智能体的 `listen` 清单。
**后果**：机器人根本收不到这个群的消息，策略完全不触发。
**正确做法**：设完群策略，立刻确认 `configs/agents.json` 的 `listen` 包含该群。这是最容易被忘、又最致命的一步。
</anti_pattern>

<anti_pattern name="群专属提示重复了分级政策或人格">
**问题**：在 `systemPromptAppend` 里又写一遍【这是公开群、不要泄密】，或又描述一遍机器人人格。
**后果**：提示冗长、互相打架，每轮都浪费预算；改分级政策时两处不同步。
**正确做法**：分级政策与人格都会自动注入，专属提示只写【本群跟同层级其他群不同的那点规则】，≤100 字。
</anti_pattern>

<anti_pattern name="改了配置不重启">
**问题**：改完 `chat-policies.json` / `agents.json` / `admins.json` 就以为生效了。
**后果**：配置在启动时缓存，运行中的进程仍用旧值，验证时一头雾水。
**正确做法**：改配置 → 重建 → 重启 serve。会话级变更（层级 / 专属提示）还要重开已存在的会话。
</anti_pattern>

<anti_pattern name="让模型自己判断能不能看">
**问题**：把【这条记忆只有管理员能看】写进提示，指望模型自觉不泄露。
**后果**：模型会照单全收它拿到的一切；一旦记忆已注入，提示里的【别说出去】形同虚设。
**正确做法**：可见性 / 命名空间在代码层闸控，模型只拿过滤后的结果。`admin_only` 由 `isAdmin` 在服务端放行，绝不靠提示自律。
</anti_pattern>

<anti_pattern name="所有群一套提示、所有人共用一段上下文">
**问题**：图省事不分群、不分人，全用一份系统提示、不利用命名空间。
**后果**：直接违背这套机制的初衷——机器人在公开群和工作群一个样、对 A 和对 B 记串了。
**正确做法**：至少按层级区分群、按 `user:` 区分人；需要群内差异再加 `group_user:`。差异化是这套设计存在的理由。
</anti_pattern>

<anti_pattern name="让自动沉淀的记忆超出注入预算">
**问题**：设计群组热词 / 自动摘要时不管单条长度。
**后果**：群组记忆 ≤500、个人记忆 ≤300 字的预算会把超出部分截断，关键信息可能被切掉。
**正确做法**：让会持续增长的记忆采用【滚动一份、控制在预算内】的写法，而非不断追加新行。
</anti_pattern>
