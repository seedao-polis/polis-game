# 系统提示如何按群、按人组装

<overview>
理解【记忆与分级政策怎么进入提示】，才能预测一次对话里机器人到底带了哪些上下文。提示分两层组装：**系统提示**（按群组装，相对静态）与**每轮提示**（按人按轮注入过滤后的记忆）。本文说明两层的拼装顺序与时机。
</overview>

<system_prompt_layer>
## 第一层：系统提示（按群组装）

每开一个 (群, 人) 会话时，系统提示按固定顺序拼装，段与段之间用 `---` 分隔：

```
人格档（soul 的若干 persona 文件，按序拼接）
        ↓ ---
静态记忆（soul 自带的 playbook / 札记，注入为【## 你的记忆】块）
        ↓ ---
分级政策文字（当带了 chatId：按该群层级取政策文字）
        ↓ ---
群专属提示（当该群填了 systemPromptAppend：叠在分级政策之后）
```

关键点：

- **分级政策与群专属提示只有【带了 chatId】时才追加**。没有群上下文（如命令行直接问答）就只有人格 + 静态记忆。
- **分级政策永远先于群专属提示**——所以群专属提示是在分级政策的基础上【再加规则】，不必重复分级政策已说的话。
- 这一层相对静态：同一个群、同一个人，多轮对话共用同一份系统提示。
</system_prompt_layer>

<per_turn_layer>
## 第二层：每轮提示（按人按轮注入过滤后的记忆）

每轮用户发言时，在身份上下文之后、用户消息之前，注入一段过滤后的 `【背景记忆】`：

```
身份上下文（点明当前是谁：open_id 等）
        ↓
【背景记忆】（站在 (当前群, 当前人) 视角，过 Policy Filter 后的记忆，按字数预算裁剪）
        ↓
用户这轮的消息
```

要点：

- 注入前会带上 `isAdmin`（当前人是否管理员）——决定 `admin_only` 记忆要不要给。
- 缺群或缺人上下文（如命令行 `ask`）则**跳过**这段注入。
- 取记忆是 best-effort：万一取失败也绝不挡回复，只是这轮少了背景记忆。
- 这一层是【每轮重算】的：所以新写入的记忆下一轮就能生效，不必重开会话。
</per_turn_layer>

<auto_memory>
## 记忆从哪来：自动摘要与群组热词

设计策略时要知道有两条【自动长出记忆】的路径，它们会无声地往命名空间里写东西：

**自动摘要（个人）**——每隔若干次成功回复，系统会撈该 (群, 人) 的近期消息，浓缩成【稳定的长期事实 / 偏好】，**滚动写一份**（固定语义键、不增长）到 `user:{open_id}` / `private`。这就是【机器人越聊越懂你】的来源，也是 `tier-policy.md` 那条已知限制的来源（工作群对话可能被摘进个人记忆）。

**群组热词（群）**——确定性地（不依赖模型）统计某群近期高频词，写一份到 `group:{chat}` 的热词记忆，经第一层路径自动进该群的群组记忆。

设计时若不希望某类内容被自动沉淀，要在策略说明里点出来，或调整这两条路径的触发（落点见 `apply-in-code.md`）。
</auto_memory>

<implications>
## 对设计的影响

- 要改【这个群机器人能说什么】→ 改分级层级或群专属提示（系统提示层），重开会话或重启后生效。
- 要改【这个人机器人记得什么】→ 增删对应命名空间的记忆（每轮提示层），下一轮即生效。
- 要预测【这次对话到底带了什么】→ 系统提示层（人格 + 静态记忆 + 分级 + 专属）+ 每轮层（过滤后的背景记忆）。用 `scripts/preview_policy.py` 或 `agent memory preview` 把每轮层那部分先模拟出来。
</implications>
