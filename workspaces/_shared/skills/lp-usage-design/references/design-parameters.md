<parameters>
## 可调参数总览

| 参数 | 默认 | 决定什么 |
|------|------|----------|
| 单次扣费 cost | 0.1（基线） | 一次对话消耗多少 → 一次发放能聊多少次 |
| 初始发放 initial | 120 | 新用户起步额度 |
| 命令计费 | 全免费 | 哪些命令消耗 LP |
| 每日补底 floor | 10 | 耗尽用户每天的最低续航 |
| 每日签到 checkin | 3 | 主动领取的每日额外额度 |
| 余额门槛 gating | = cost | 低于多少就不答 |
| 退费 refund | 全额退 | 出错 / 中断是否退 |
| 全员重置 reset | 设为 120 | 调参 / 开服时拉平所有人 |
</parameters>

<cost>
## 单次扣费（核心旋钮）

最重要的一个数：一次对话扣多少 LP。它和初始发放一起决定【一次发放够聊多少次】。

- 反推法：`单次扣费 = 初始发放 ÷ 目标续航次数`。想 120 分聊约 400 次 → 0.3；聊约 1200 次 → 0.1。
- 小数完全可行（余额按一位小数显示）。常见取值 0.1 / 0.2 / 0.3 / 0.5 / 1。
- 不同智能体可以不同：一个偏【轻量高频】的设小（0.1），一个偏【重度低频】的设大（0.5~1）。
- 落点是对话频道里的扣费常量（见 apply-in-code.md）。要做到【每个智能体不同】，让这个常量按当前 soul / 配置取值，而不是写死一个。
</cost>

<initial>
## 初始发放

新用户初次互动一次性发放的额度（同时发 `first_contact` 徽章）。它是【一次发放续航】的分子。设大 = 新人体验更宽裕但通胀快；设小 = 更依赖签到 / 补底。改它不影响老用户（只在初次建档时发一次）。
</initial>

<commands>
## 命令计费

默认所有命令免费。设计原则：

- **查询 / 自助类免费**（看余额、看排行、看帮助、签到）——让用户【了解自己的状态】不该花钱，否则体验很差。
- **只对真正调用智能体生成内容的路径扣费**。
- 若确实想让某个重命令计费（如一个会触发长生成的命令），在该命令实现里调 `spendPt(ctx.senderOpenId, 命令扣费, '<reason>')`，扣成功才执行、并自己加 footer；不足则回门槛文案。
- 罗列方案时给一张【命令 → 免费 / 扣费额】表，逐条明确。
</commands>

<floor>
## 每日补底

每天把余额低于 floor 的人补到 floor（不是加 floor）。它决定**耗尽用户每天的免费续航** = `floor ÷ 单次扣费`。floor=10、cost=0.1 → 每天 100 次；cost=0.3 → 约 33 次。设大 = 更慷慨的每日免费量；设 0 = 不补底（耗尽就只能靠签到 / 任务）。
</floor>

<checkin>
## 每日签到

主动领取的每日额度，叠加在补底之上。一个耗尽用户当天可聊 = `(floor + checkin) ÷ cost`。签到鼓励每日活跃；设 0 = 关闭签到激励。
</checkin>

<gating_param>
## 余额不足门槛

默认【余额 < 单次扣费就不答】。可调高（例如要求至少留 N 分），或自定义不足时的文案（提示去签到 / 做任务 / 等补底）。门槛只挡走智能体的对话，不挡命令。
</gating_param>

<refund_reset>
## 退费与重置

- **退费**：先扣后答的模式下，生成失败要退（`refund_on_error`）、中断重跑要先退再重扣（`refund_interrupted`）。除非有意【失败也收费】，否则都应退。
- **全员重置**：上线、调参、改了扣费规则后常需要把所有人拉平到同一起点。用 `resetAllPtTo(target)`（CLI `reset-all-pt [--to n]`），它既升也降，只对有变化的人写流水。把它列进方案的【运维动作】里。
</refund_reset>

<formulas>
## 续航计算公式

- **一次发放续航**（次） = `initial ÷ cost`
- **每日续航**（耗尽用户，次/天） = `(floor + checkin) ÷ cost`
- **耗尽天数**（无任何补给） = `initial ÷ (cost × 每日预估互动数)`
- **混合命令消耗**：若一部分互动是计费命令，按各自 cost 加权平均成【等效单次成本】再套上面公式。

`scripts/lp_runway.py` 就是把这些算出来，避免手算出错。
</formulas>

<recipes>
## 常见配方

| 配方 | initial / cost / floor / checkin | 效果 |
|------|----------------------------------|------|
| 轻量高频 | 120 / 0.1 / 10 / 3 | 一次发放 1200 次；每日续航 130 次。日常陪聊型。 |
| 中度 | 120 / 0.3 / 10 / 3 | 一次发放 400 次；每日续航约 43 次。多数智能体的稳妥默认。 |
| 重度低频 | 120 / 1 / 5 / 3 | 一次发放 120 次；每日续航 8 次。鼓励【想清楚再问】。 |
| 仅签到补给 | 100 / 0.5 / 0 / 5 | 不补底，耗尽后每天只有签到 10 次；强激励每日签到。 |

把目标配方填进 `templates/lp-economy-spec.md`，再用脚本核对。
</recipes>
